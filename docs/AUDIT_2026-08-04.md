# Artista compatibility and integrity audit — 2026-08-04

This pass used Paint.NET 5.1.9 screenshots as the interaction reference and reviewed the highest-risk editing paths: canvas navigation, layer targeting and lifecycle, floating selections, clipboard/paste, file drag/drop, history/dirty tracking, and save/export boundaries.

## Fixed findings

1. **Critical — layer row clicks never changed the active layer.** The list stores `ListBoxItem` wrappers, while the old handler tested the selected object as the wrapped row. Layer activation now unwraps the row correctly, commits any pending tool operation, and targets subsequent drawing to the selected layer. The UI test draws on a lower layer and proves the unselected top layer is unchanged.
2. **Canvas movement stopped short of Paint.NET's corners.** Pan bounds now allow the image's left/right and top/bottom edges to align exactly with the viewport edges, for canvases both smaller and larger than the viewport.
3. **Oversized paste discarded off-canvas source pixels.** Paste now offers Paint.NET-style **Expand canvas**, **Keep canvas size**, and **Cancel** choices. Keep-canvas paste retains the full source as movable floating pixels; Expand grows the document and is fully undoable.
4. **Drag/drop always opened files.** Dropped images now offer **Open**, **Add layer**, and **Cancel**. Multiple dropped files apply the selected operation to each file; `.artz` projects can be flattened into imported layers.
5. **Move Selected Pixels could erase content on a click without movement.** Pixels remain exact until the pointer actually moves, and no no-op history entry is created.
6. **Pending tools could cross layer/history/save boundaries.** Layer selection and operations, History jumps, Save, Export, Copy, Paste, and imports now commit the active operation at the appropriate boundary so previews cannot land on another layer or be omitted from saved output.
7. **Layer reorder history was pushed before mutation.** Reordering now captures first, mutates second, and pushes last, avoiding panel refresh in the middle of a drag operation.
8. **Dirty tracking confused history depth with document identity.** A divergent edit made after Undo could previously look clean when it reached the same undo count as the last save. History states now have unique identities across branches.
9. **Cut deleted pixels even when clipboard copy failed.** Cut now removes pixels only after Windows confirms the clipboard data was persisted.
10. **Startup chrome could begin outside the usable display.** The main window now explicitly uses normal resizable chrome and is clamped to the desktop work area, keeping Minimize, Maximize, Close, and the title bar reachable on smaller displays.
11. **Explorer could cover the drag/drop decision.** The modal prompt is deferred until Explorer's OLE drop callback returns, then activates as a topmost owned window.
12. **Copy without a pixel selection captured a merged full canvas.** Ctrl+C now copies only the active layer and crops transparent margins when there is no explicit pixel selection.
13. **Pasted pixels could move but not resize.** Move Selected Pixels now draws four corner handles for pasted content, resizes with bilinear sampling, preserves aspect ratio while Shift is held, and records move/resize as one undoable operation.
14. **Layer deletion required the button/menu.** Delete removes the selected layer while the Layers list has keyboard focus; on the canvas it continues to clear selected pixels.
15. **Panels only docked on the right.** Colors, History, and Layers now snap to left, right, or top, and persist their chosen edge.
16. **Paste always created a layer named “Pasted layer.”** Clipboard pixels now float inside the layer selected at paste time. Moving or resizing them restores the pre-existing target pixels beneath the old preview position, and no layer is added.
17. **Enter left Move Selected Pixels selected.** Enter now commits the floating operation and clears its selection outline.
18. **Panel snap edges were invisible.** Dragging a floating Tools, Colors, History, or Layers window now reveals large labeled LEFT, TOP, and RIGHT targets; the snap radius is also more forgiving.
19. **Repeated resize gestures accumulated resampling damage.** Pasted transforms now keep one immutable source image. Every preview is rebuilt from it, so releasing/reapplying Shift restores the true source ratio and never uses a temporary distorted preview as the next source.
20. **Resizable pixels had no rotation control.** The transform frame now includes a round rotation handle; Shift snaps rotation to 15-degree increments, and all previews remain part of the same undoable floating operation.
21. **Enter did not finish Rectangle Select.** Enter now commits and deselects Move Selected Pixels and all selection workflows, while retaining normal commit behavior for drawing tools.
22. **Tools was a small fixed strip rather than a familiar panel.** Tools is now a larger two-column Paint.NET-style floating panel with the familiar order, an F5 toggle, and left/right/top docking. It reflows horizontally when docked above the canvas.
23. **Tool artwork was too abstract and monochrome.** All 24 tools now use original colored vectors with familiar paint-editor silhouettes: blue selections and movers, a starred wand, gold hand, spilling bucket, multicolor gradient, media-colored brush/pencil/eraser/picker, and distinct text/curve/shape glyphs. Dark and light renders are visually verified.

## Intentional boundaries

- **Add layer** keeps the current canvas dimensions and centers/clips the imported image to that canvas. Choose **Open** when the imported file's native dimensions must be preserved as a document.
- A floating pasted image may extend beyond the document, but its marching-ants outline is necessarily clipped to the document canvas.
- Existing documented format limitations remain: `.pdn` is unsupported and WebP is decode-only through the installed Windows codec.
